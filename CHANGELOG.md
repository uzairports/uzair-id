# Changelog

Все заметные изменения `uzairports/uzair-id`. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют
[семантическому версионированию](https://semver.org/lang/ru/).

## [Unreleased]

### Added

- Эндпоинт `POST {prefix}/logout-device/{token}` (`uzair.logoutDevice`) — завершение
  одного конкретного входа аккаунта, не трогая браузер, из которого его завершают.
  Поиск строки ограничен текущим аккаунтом, поэтому чужая возвращает 404, а не отказ;
  завершение собственного входа передаётся в `logout()`, чтобы сессия ушла вместе с ним.
- Команда `uzair:prune` (`php artisan uzair:prune`) — специализированная консольная
  команда очистки устаревших OAuth-токенов с автоматическим отзывом грантов на SSO
  (если включено `revoke_on_prune`).
- Метод `Uzair::resolveUserUsing(?callable $callback)` — хук для кастомизации создания
  или сопоставления модели локального пользователя из профиля Socialite.
- Настройки `logout_endpoint` (`UZAIR_LOGOUT_ENDPOINT`, по умолчанию `/api/v1/oauth/logout`)
  и `user_endpoint` (`UZAIR_USER_ENDPOINT`, по умолчанию `/api/user`) — возможность гибкой
  настройки путей API авторизации провайдера.
- Поддержка распознавания браузера Samsung Internet (`SamsungBrowser`) в методе
  `OauthToken::deviceLabel()`.
- Настройка `revoke_endpoint` (`UZAIR_REVOKE_ENDPOINT`) — адрес RFC 7009 для отзыва
  refresh-токена при завершении входа. Пусто по умолчанию: адрес не угадывается, чтобы
  установка без такого эндпоинта не платила неудачным запросом на каждом выходе.
- Настройка `revoke_on_single_session` (`UZAIR_REVOKE_ON_SINGLE_SESSION`, по умолчанию
  `true`) — отдавать ли гранты SSO, когда `single_session` завершает остальные входы
  аккаунта. Отзыв стоит round-trip на каждый вход, и платит за него тот самый запрос,
  которого ждёт пользователь: аккаунт на десятке устройств выждет десяток таймаутов,
  прежде чем увидит дашборд. Выключается там, где это ожидание реально; входы при этом
  всё равно заканчиваются здесь — строки удаляются, сессии стираются, `uzair.token`
  отказывает им на следующем запросе, — отдаётся только удалённое снятие гранта.
  `EndSessions::__invoke()` принимает это третьим аргументом (`revoke:`).
- `OauthToken::keepAlive()` — отметка о том, что вход всё ещё используется.
- Настройка `revoke_on_prune` (`UZAIR_REVOKE_ON_PRUNE`, по умолчанию `true`) — отдавать
  ли гранты SSO при уборке. Каждая строка стоит запросов отзыва, а уборка может идти по
  тысячам строк; отключается там, где такой объём реален, а гранты истекают сами.
- `EndSessions::surrender()` — отдать грант входа, не трогая строку. Это то, что нужно
  уборке: строку удаляет она сама, а сессию, которую строка называла, хранилище собрало
  задолго до того, как уборка до неё дошла.

### Removed

- **Эндпоинт `POST {prefix}/logout-all` (`uzair.logoutAll`) и метод контроллера
  `logoutAll()`.** Завершить все входы аккаунта — значит отдать SSO каждый грант по
  очереди, а один запрос не может отвечать за неизвестное заранее количество: аккаунт с
  десятком устройств выждал бы десяток таймаутов отзыва, прежде чем браузер услышал бы
  хоть что-то, и отказ по любому из них не повторялся. Устройства завершаются по одному
  через `uzair.logoutDevice` — из списка входов, который аккаунт и так видит. Уберите
  ссылки на маршрут и его имя из своих шаблонов.

### Changed

- **`config/`, `database/` и `lang/` вынесены из `src/` в корень пакета.** `src`
  остаётся корнем PSR-4 и содержит только классы — как в first-party пакетах Laravel.
  Публикуемые файлы, теги публикации и API не изменились; правка нужна только тем,
  кто ссылался на внутренние пути пакета напрямую.
- **`oauth_tokens.session_id` проиндексирован.** Callback ищет вход, который тот же
  браузер держал до повторного входа, по одному только `session_id` — строка может
  принадлежать другому аккаунту (общий компьютер, вторая учётная запись), поэтому
  запрос нельзя ограничить текущим. Уникальная пара `(user_id, session_id)` начинается
  с `user_id`, а индекс нельзя войти с середины, — так что без своего индекса каждый
  вход читал `oauth_tokens` от начала до конца. Таблица держит строку на живой вход,
  то есть скан рос вместе с числом вошедших и был хуже всего ровно в тот час, когда
  все входят. Новые установки получают индекс из `create_oauth_tokens_table`,
  существующие — из `index_oauth_tokens_by_session` в `uzairid-upgrade-migrations`.
- `EndSessions::__invoke()` удаляет строки одним запросом, а не по одной. Это массовый
  путь — у аккаунта может быть сколько угодно входов, — и выполняется он внутри запроса,
  которого кто-то ждёт: при `single_session` внутри самого callback. Там, где отзыв
  грантов отключён (`revoke_on_single_session=false`, `revoke_on_prune=false`), эти
  удаления и составляли всю стоимость вызова.
- **Пакет требует Laravel 13.** Ограничение `illuminate/*` сужено с
  `^11.0|^12.0|^13.0` до `^13.0`. Поддержка 11 и 12 была объявлена, но никогда не
  проверялась и не могла быть проверена: `orchestra/testbench: ^11.2` требует
  `laravel/framework: ^13.23.0` и конфликтует со всем, что ниже, а матрица CI и так
  состояла из одного `13.*`. Обещание, за которым не стоял ни один прогон тестов,
  снято вместо того, чтобы делать вид, что оно выполняется.
- В блоке `single_session` опубликованного конфига описана цена настройки: каждый
  завершаемый вход отдаётся SSO по очереди внутри callback, которого ждёт браузер.
- При завершении входа отдаётся не только access-токен, но и refresh-токен (если
  `revoke_endpoint` задан). Ничто в OAuth не обещает, что снятие access-токена снимает
  выданный вместе с ним refresh-токен, а переживший выход refresh-токен — это путь
  обратно в аккаунт для того, у кого осталась копия. Оба отзыва выполняются независимо,
  так что отказ по одному не отменяет второй.
- Уборка (`model:prune`) отдаёт грант каждой собираемой строки SSO, а не только удаляет
  её. Закрытый браузер не выходит, поэтому без этого его refresh-токен оставался
  действующим и после того, как здесь на него ничто не указывало, — единственный путь,
  на котором вход заканчивался с живым грантом. Отказ SSO пишется в лог и не мешает
  строке уйти.
- `uzair.token` продлевает строку входа, пока браузер продолжает ходить с запросами
  (не чаще одного раза за половину `session.lifetime`), и передаёт найденный вход
  модели пользователя, так что `currentToken()` в контроллере или во view больше не
  делает второй такой же запрос.

### Fixed

- **Конфиг отсылал к удалённому эндпоинту.** Блок `single_session` советовал тем, кому
  нужно завершить остальные входы, воспользоваться «sign-out everywhere», хотя
  `logout-all` в этом же релизе и удалён, а `Uzair::routes()` прямо утверждает
  обратное. Конфиг публикуется в хост-приложение через `vendor:publish`, поэтому
  интегратор читал именно неверную версию. Тот же призрак убран из докблока
  `EnsureAccessTokenIsFresh`.
- **Прунинг мог удалить действующий вход.** `updated_at` писался только при обновлении
  токена, поэтому вход с access-токеном, живущим дольше окна прунинга (например,
  восьмичасовой токен при `session.lifetime=120`), оставался нетронутым, пока владелец
  работал, — и `model:prune` удалял его, после чего пользователя выбрасывало из
  приложения. Теперь `updated_at` означает «когда браузер приходил в последний раз».
- `currentToken()` не кешировал отрицательный ответ: сессия без входа приводила к
  запросу в базу при каждом обращении.
- **Сохранённый email затирался, если SSO его не прислал.** Имя в такой ситуации
  оставалось прежним, а адрес перезаписывался на `null`, хотя почта на стороне
  провайдера необязательна и вход без неё не означает, что её отозвали. Теперь
  сохранённое значение остаётся на месте; изменившийся адрес по-прежнему записывается.
- **Запрос без сессии мог завершить чужой вход.** Такому запросу — API-клиенту,
  консольной команде — доставался последний вход аккаунта, и если продлить токен не
  удавалось, строка удалялась: устройство, которое этот запрос не делало, выбрасывало из
  приложения. Отказ запросу остался, удаление строки — только для той сессии, которой
  она принадлежит.
- В документации по уборке `model:prune` вызывался без `--model`. Команда ищет модели
  только в `app/Models` приложения, поэтому `OauthToken` в неё не попадал и уборка
  молча не делала ничего.
- **Отказ в refresh-токене вызывал 503 вместо редиректа на повторный вход.** Метод
  `RefreshAccessToken::grantWasRejected` теперь распознаёт HTTP 401 и коды OAuth 2.0
  (`invalid_grant`, `invalid_token`, `unauthorized_client`), предотвращая циклическую
  ошибку недоступности сервиса при отозванном или просроченном токене.
- **Предыдущий вход не очищался при смене пользователя в том же браузере.** Метод
  `endPreviousLogin` в контроллере теперь удаляет запись предыдущей сессии браузера
  независимо от того, принадлежала ли она тому же `user_id`.
- **`EndSessions` не удалял сессии по `session_id` завершаемых токенов.** Метод
  `deleteStoredSessions` теперь удаляет записи из таблицы сессий базы данных как по
  `user_id`, так и по собранным `session_id` токенов.
- Удалён пустой каталог `src/Jobs`.
