# Установка

[← Оглавление](README.md)

```bash
composer require uzairports/uzair-id
```
Опубликуйте конфигурацию и миграции:
```bash
php artisan vendor:publish --tag=uzairid-config
php artisan vendor:publish --tag=uzairid-migrations
```
```bash
php artisan migrate
```

Публикуются базовые миграции (`uzairid-migrations`):
- `add_uzair_id_to_users_table` — добавляет `uzair_id` в таблицу пользователей;
- `create_oauth_tokens_table` — создаёт таблицу `oauth_tokens` со структурой «одна строка — один вход» (поддерживает integer, UUID и строковые идентификаторы пользователей). Колонка `user_id` повторяет тип ключа в таблице пользователей и получает внешний ключ с `ON DELETE CASCADE` — при удалении пользователя его строки в `oauth_tokens` удаляются вместе с ним. Если таблица пользователей на момент запуска миграции ещё не создана, ссылаться не на что: колонка создаётся без внешнего ключа.

> Каскад — это защита целостности, а не способ завершить вход. Удаление на уровне БД проходит мимо Eloquent: события модели не срабатывают, кэш входов не инвалидируется, и **гранты не отзываются у UzAirports ID** — access и refresh токены удалённого пользователя остаются действительными до собственного истечения. Приложение, удаляющее пользователей, должно сначала завершать их входы через [`EndSessions`](sessions.md#завершение-входов).

> Внешний ключ добавляется только при создании таблицы. Установки, где `oauth_tokens` уже существует, продолжают работать с прежней колонкой без ограничения — миграции обратного заполнения для этого нет, поскольку она потребовала бы удаления «осиротевших» строк.

## Миграции таблицы `users`

Опциональные миграции для модификации таблицы `users` (удаление `password` и снятие ограничений с `email`):
```bash
php artisan vendor:publish --tag=uzairid-user-migrations
```

> ⚠️ **Внимание: колонка `password` будет удалена!**  
> Миграция `remove_password_column_from_users_table` (входит в тег `uzairid-user-migrations`) **удаляет колонку `password`** из таблицы `users`. В чистом SSO-сценарии учетные данные хранятся исключительно на стороне провайдера UzAirports ID.  
> Если ваше приложение использует гибридную схему аутентификации (например, сохраняет локальный вход по паролю для администраторов) или если вы не хотите удалять столбец:  
> - **Не публикуйте и не запускайте** миграцию удаления `password`;  
> - Убедитесь, что в таблице `users` колонка `password` объявлена как `nullable`, либо настройте кастомное создание пользователя через `Uzair::resolveUserUsing(...)`, чтобы при создании SSO-пользователей не возникало ошибок отсутствия значения по умолчанию.

> ⚠️ **Ограничения на `email` снять придётся в любом случае.**  
> Миграция `relax_email_column_on_users_table` (тот же тег) снимает с `users.email` уникальность и `NOT NULL`. В стандартном Laravel колонка объявлена и уникальной, и обязательной, а провайдер не обещает ни того, ни другого: адрес может не прийти вовсе и может повторяться у разных учётных записей. Пока ограничения на месте, вход упадёт в трёх случаях:
> - у пользователя SSO адрес совпадает с адресом уже существующей локальной учётки, а `link_by_email` выключен (по умолчанию) — новая запись не вставится;
> - две разные личности в SSO делят один адрес — войдёт только первая;
> - провайдер не прислал адрес — вставлять в `NOT NULL` нечего.
>
> Если снимать ограничения нельзя, единственный поддерживаемый путь — своё создание пользователя через `Uzair::resolveUserUsing(...)`.

Что бы вы ни выбрали, отказ базы на первом входе разбирать вручную не придётся: пакет читает таблицу и пишет в лог строку `error` с её именем, списком колонок без значения по умолчанию (`password` — обычно как раз он), признаком уникальности `email` и командой публикации. Смотрите её, если вход отвечает «authentication failed» сразу после установки.

## Обновление со старых версий

```bash
php artisan vendor:publish --tag=uzairid-upgrade-migrations
```

- `add_session_id_to_oauth_tokens_table` и `make_oauth_tokens_per_session` — переход со схемы
  «один токен на аккаунт» на «одна строка — один вход»;
- `add_personal_access_token_id_to_oauth_tokens_table` — колонка, под которой записан вход
  мобильного клиента с токеном Sanctum (см. [Мобильное приложение](mobile.md));
- `add_oidc_columns_to_oauth_tokens_table` — колонки `sid` и `id_token` для OpenID Connect
  (см. [Выход на стороне UzAirports ID](sessions.md#выход-на-стороне-uzairports-id-openid-connect));
- `index_oauth_tokens_for_pruning` — индекс по `updated_at` для уборки (см. [Уборка](sessions.md#уборка));
- `index_oauth_tokens_by_session` — индекс по `session_id`. Вход, который браузер держал
  до повторного входа, ищется по одному только `session_id`: строка может принадлежать
  другому аккаунту, поэтому запрос нельзя ограничить текущим, а уникальная пара
  `(user_id, session_id)` начинается с `user_id` и такому запросу не помогает. Без индекса
  каждый вход читал `oauth_tokens` целиком.

Установки, созданные начиная с этого релиза, получают оба индекса сразу из
`create_oauth_tokens_table`.

Все идемпотентны: то, что уже есть в схеме, миграция не трогает.

> Обновляетесь с версии, где у пользователя был один токен? Строки без `session_id` при
> миграции удаляются: они держат токен для браузера, на который больше нельзя указать.
> Пользователи войдут заново.

## Долгоживущие процессы

Пакет держит в статических свойствах кеши и признаки «предупреждение уже записано», которые
не должны переживать запрос. Под Octane `UzairServiceProvider` сбрасывает их сам на событиях
завершения запроса, задачи и тика. Если приложение работает в другом долгоживущем рантайме
(RoadRunner, FrankenPHP worker mode без Octane и т. п.), вызывайте сброс в конце каждого
запроса:

```php
\Uzairports\Uzairid\Uzair::flushState();
```

Резолверы, зарегистрированные при загрузке (`resolveUserUsing()`,
`updateUserAttributesUsing()`, `treatRequestsAsLocalWhen()`), при этом сохраняются.

## Тестирование приложения

Для тестов, которым нужен вошедший через SSO пользователь, есть два хелпера:

```php
use Uzairports\Uzairid\Uzair;

$user = Uzair::fakeUser(['name' => 'Test User']); // создаёт аккаунт с uzair_id
$login = Uzair::fakeLogin($user, 'session-id');   // строка oauth_tokens для этой сессии
```

`fakeUser()` принимает любые атрибуты модели. `uzair_id`, `name` и `email` заполняются сами,
если их не передать. `fakeLogin()` записывает вход с фиктивными токенами, которые истекают
через час, под переданным id сессии. Без второго аргумента берётся id сессии текущего
запроса, а если сессии нет — случайный. Такую строку `uzair.token` найдёт, только если id
совпадёт с id сессии запроса, который проходит через этот middleware.
