# Обновление токена

[← Оглавление](README.md)

Access token живёт ограниченное время. Пакет хранит момент истечения в колонке `expires_at`
и умеет обменивать `refresh_token` на новый access token через middleware `uzair.token`:

```php
Route::get('/dashboard', [DashboardController::class, 'index'])
    ->middleware(['auth', 'uzair.token']);
```

Middleware обновляет токен, если тот истекает в ближайшие `uzairports.refresh_leeway`
секунд (по умолчанию 60, настраивается через `UZAIR_REFRESH_LEEWAY`). Если SSO отказывается
обменивать refresh token, токен удаляется, сессия сбрасывается и поднимается
`AuthenticationException` — браузер уезжает на маршрут из `uzairports.login_route` с
сохранением исходного адреса, а запрос с `Accept: application/json` получает `401`. Если
маршрута с таким именем нет, пользователь отправляется на корень сайта, а несоответствие
пишется в лог — конфигурационная опечатка не превращается в 500. Завершение входа здесь
рассылает `UzairLoggedOut` — то же событие, что и `POST /auth/logout`.

Аккаунт читается из guard приложения по умолчанию; маршрут со своим guard называет его
параметром — `uzair.token:admin` рядом с `auth:admin`, — а `uzairports.guard` задаёт guard для
всего приложения сразу. Модель провайдера guard, названного в маршруте, может отличаться от
модели `uzairports.guard`, но обязана читать ту же таблицу аккаунтов (скажем, `Admin` поверх
`users`): входы найдены по одному `user_id`, и модель со своей таблицей получила бы чужой вход.
Такой маршрут отвечает `503`. Если провайдер guard не называет Eloquent-модели
(`Auth::viaRequest()`, свой драйвер), проверка идёт по `uzairports.guard`, как и без параметра.

## Параллельные запросы

UzAirports ID ротирует refresh token, поэтому потратить его можно только один раз: два
параллельных запроса одного и того же браузера, обменивающих один и тот же токен, оставили бы
проигравшего с уже аннулированным. Обмен идёт под блокировкой (`Cache::lock`), и тот, кто её дождался, читает
токен, сохранённый победителем, вместо повторного обмена. Блокировку держит кеш, поэтому в
продакшене он должен быть общим для всех процессов приложения (`database`, `redis`,
`memcached`): `array` живёт внутри одного процесса и запросы между собой не разведёт, а
`file` общий только в пределах одного сервера — см. примечание к `lock_store` в
`config/uzairports.php`.

## Ручное обновление

```php
use Uzairports\Uzairid\Actions\RefreshAccessToken;
use Uzairports\Uzairid\Uzair;

$login = $user->currentToken();

if ($login === null) {
    // У этого запроса нет входа — обновлять нечего.
    return;
}

// false — SSO отказал в гранте, нужен повторный вход;
// сбой провайдера или кеша — ServiceUnavailableHttpException (503).
$renewed = app(RefreshAccessToken::class)($login, Uzair::refreshLeeway());
```

Второй аргумент — тот же запас, по которому решает `uzair.token`. Под блокировкой действие
перечитывает строку и, если токен истекает позже чем через `$leeway` секунд, принимает его
без обращения к SSO: так ожидавший блокировку не тратит refresh token повторно. Поэтому при
`$leeway = 0` (значение по умолчанию) ещё не истёкший токен обновлён не будет.
