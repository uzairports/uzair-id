# Сессии и устройства

[← Оглавление](README.md)

## Несколько устройств

Строка `oauth_tokens` — это один вход, а не «токен аккаунта»: уникальна пара
`(user_id, session_id)`. Один и тот же человек может быть залогинен с телефона и с рабочего
компьютера одновременно, и у каждого браузера свой грант — ровно так, как это задумано в
OAuth: каждый обменял собственный код авторизации, значит и ротирует собственный refresh
token.

`uzair.token` ищет токен по паре, поэтому чужая строка для запроса не существует. Если строки
для этой сессии нет, а `uzair_id` у пользователя заполнен, вход был завершён: сессия
сбрасывается и поднимается `AuthenticationException` — браузер уезжает на `login`,
API-клиент получает `401`. Аккаунтов без `uzair_id` это не касается, локальные учётки живут
как жили.

У запроса без сессии — API-клиент, консольная команда — браузера нет, и ищется он только
среди входов, которые тоже не называют браузера: `session_id` потому и nullable, что вход
может быть выдан вне сессии. Чужая строка такому запросу не достаётся ни для чтения, ни
для завершения.

> Отсюда практическое следствие для API. Повесив `uzair.token` на маршрут без сессии, вы
> получите `401` для пользователя с заполненным `uzair_id`, у которого нет входа с пустым
> `session_id`, — браузерный вход за него не отвечает. Либо создайте такой вход отдельно,
> строкой `oauth_tokens` с `session_id = null`, либо скажите пакету, что этот запрос
> аутентифицировало само приложение — см. «Запрос без сессии: Sanctum и API» ниже.

Раньше здесь отдавался последний вход аккаунта, то есть чей-то браузер. Читать через него
токен было наименьшей из бед: запрос продлевал этот вход на каждом вызове, поэтому
брошенный браузер никогда не доживал до `prunable()` и его грант не сдавался, — а
ротируемый refresh token тратился ради вызывающего, который прочитать результат всё равно
не может (`HasUzairToken::currentToken()` без сессии отдаёт `null`).

## Смена id сессии

`$request->session()->regenerate()` — обычное дело в Laravel: подтверждение пароля, второй
фактор, `logoutOtherDevices()`, любое ужесточение привилегий в приложении. Payload сессии при
этом сохраняется, а id меняется — и вход, названный старым id, переезжает на новый вместе с
браузером. Ничего настраивать не нужно и ничего вызывать тоже: сессия сама помнит, под каким
id записан её вход, и `uzair.token` сверяется с этой пометкой, когда по текущему id не нашёл
ничего. Переезд ограничен аккаунтом, за который сессия залогинена: id называет сессию, а не
владельца, и чужую строку он не заберёт.

Без этого следующий же запрос после регенерации не находил входа для своей сессии и выбрасывал
залогиненного пользователя обратно в SSO, а строка оставалась висеть с грантом, который никто
не сдаст до уборки. `POST /auth/logout` и `POST /auth/logout-device/{token}` сверяются с той же
пометкой — на них `uzair.token` не висит, а выход обязан найти вход, чтобы сдать его грант.

## Гибридная схема: вход по паролю

`uzair_id` заполняется навсегда, поэтому по нему нельзя отличить завершённый SSO-вход от
собственного парольного входа приложения — и `uzair.token` отказывал пользователю, который
хоть раз заходил через SSO, а потом вошёл обычной формой. Скажите пакету, что эту сессию
аутентифицировало само приложение:

```php
use Uzairports\Uzairid\Uzair;

if (Auth::attempt($credentials)) {
    $request->session()->regenerate();

    Uzair::markSessionAsLocal($request);
}
```

Вызывайте **после** входа: `Auth::attempt()` мигрирует сессию, и пометка, записанная раньше,
уйдёт вместе со старой. Она живёт ровно столько, сколько сессия: выход её обнуляет, а вход
через SSO снимает — с этого момента у браузера есть строка `oauth_tokens`, и её завершение
`uzair.token` обязан замечать. Пометка спрашивается только тогда, когда вход не найден, так что
сессии с настоящим SSO-входом обновляют токен как обычно.

> Это утверждение о том, как аутентифицирован браузер, поэтому делать его вправе только то
> место, которое его аутентифицировало, и только для сессии, которую оно только что
> аутентифицировало. `Uzair::sessionIsLocal($request)` отвечает, помечена ли текущая сессия.

## Запрос без сессии: Sanctum и API

`markSessionAsLocal()` пишется в payload сессии, поэтому о запросе без сессии он не говорит
ничего — а `uzair_id` у аккаунта заполнен навсегда. API-клиент с токеном Sanctum оказывался в
том же тупике, что и парольный вход до пометки: отказ на каждом запросе и нечем возразить.
Скажите правилом, какие запросы аутентифицировало само приложение:

```php
use Illuminate\Http\Request;
use Uzairports\Uzairid\Uzair;

// AppServiceProvider::boot()
Uzair::treatRequestsAsLocalWhen(
    fn (Request $request): bool => $request->user()?->currentAccessToken() !== null,
);
```

Правило регистрируется один раз при загрузке приложения — как резолвер пользователя, и, как
он, не сбрасывается между запросами на Octane. Если решение принимается не правилом, а
собственным middleware, есть императивная форма: `Uzair::markRequestAsLocal($request)` живёт
в attribute bag запроса и ничего не говорит о других запросах.

Спрашивается это только тогда, когда вход не найден: запрос, у которого есть строка
`oauth_tokens` с `session_id = null`, обновляет токен как обычно. Так что выбор между двумя
путями — про то, чем владеет API-клиент: собственным грантом SSO (тогда строка) или
аутентификацией приложения (тогда правило).

## Guard

Всё, что пакет делает с аутентификацией, идёт через guard: callback логинит, `logout`
разлогинивает, `uzair.token` читает аккаунт. По умолчанию это guard приложения. Приложение со
своим guard называет его в `uzairports.guard`, а отдельный маршрут — параметром middleware,
который важнее конфига:

```php
Route::get('/admin', [AdminController::class, 'index'])
    ->middleware(['auth:admin', 'uzair.token:admin']);
```

Без этого callback открывал сессию в guard по умолчанию, а middleware искал аккаунт в том,
который назван у маршрута, — и не находил никого.

## Завершение входов

`EndSessions` делает три вещи, и каждая закрывает пробел двух других:

1. **отзывает токены в SSO.** Без этого устройство всего лишь уезжает на `login`, а UzAirports
   ID, который всё ещё держит сессию для его браузера, отвечает свежим кодом авторизации — и
   устройство заходит обратно, не показав ни одной формы;
2. **удаляет строку**, поэтому `uzair.token` отказывает этой сессии при любом драйвере сессий;
3. **удаляет саму сессию из хранилища**, поэтому устройство, чей следующий запрос не дойдёт до
   middleware, тоже теряет сессию. Драйвер `database` — одним запросом, остальные — через
   `destroy()` их собственного handler'а, то есть `file`, `redis`, `memcached` и `dynamodb`
   тоже. Не спрашиваются только `array` (сессии одного процесса) и `cookie` (хранилища нет
   вовсе: сессия едет в cookie самого браузера).

Отсюда следствие: вешайте `uzair.token` на все аутентифицированные маршруты, а не только на
те, где нужен свежий access token.

`POST /auth/logout` завершает текущее устройство, `POST /auth/logout-device/{token}` — одно
названное. Недоступность SSO не оставляет пользователя залогиненным: строка удаляется в любом
случае, а ошибка пишется в лог.

### Отзыв refresh-токена

Выход отдаёт SSO access-токен — это всё, о чём `/api/oauth/logout` узнаёт. Ничто в OAuth
не обещает, что снятие access-токена снимает выданный вместе с ним refresh-токен, а
переживший выход refresh-токен — это путь обратно в аккаунт для того, у кого осталась копия.
Если ваш экземпляр UzAirports ID предоставляет эндпоинт отзыва (RFC 7009), назовите его — и
refresh-токен будет отдаваться явно, а не в расчёте на каскад, которого может не быть:

```env
UZAIR_REVOKE_ENDPOINT=/oauth/revoke
```

Принимается как путь на хосте SSO, так и полный URL. Пусто по умолчанию: адрес не угадывается,
чтобы установка без такого эндпоинта не платила неудачным запросом на каждом выходе. Отзывы
access- и refresh-токена выполняются независимо, поэтому отказ по одному не отменяет второй.

### Завершение одного устройства

Строка входа называет себя своим `id`, и этого достаточно, чтобы завершить её из другого
браузера:

```blade
<form method="POST" action="{{ route('uzair.logoutDevice', $login) }}">
    @csrf
    <button type="submit">Завершить</button>
</form>
```

Поиск строки ограничен текущим аккаунтом, поэтому чужая не отвергается, а просто не находится
(404) — по эндпоинту нельзя выяснить, какие `id` существуют. Параметр `{token}` ограничен
цифрами: `id` строки всегда целое, а сравнение слова с колонкой `bigint` — это 404 на SQLite
и MySQL, но ошибка типа, то есть 500, на PostgreSQL. Завершение собственного входа —
это выход, и он передаётся в `logout()`, чтобы сессия ушла вместе со строкой. Запрос с
`Accept: application/json` получает `204`, обычный — редирект назад.

## Список активных входов

```blade
@foreach ($user->tokens as $login)
    {{ $login->deviceLabel() }} · {{ $login->ip_address }} · {{ $login->created_at }}
    @if ($login->is($user->currentToken())) (это устройство) @endif
@endforeach
```

`deviceLabel()` — догадка по `User-Agent`, строке, которую браузер волен выдумать: её хватает,
чтобы человек узнал свой телефон в списке, и никогда не хватает, чтобы что-то на ней решать.

## Уборка

Закрытый браузер не выходит — он просто перестаёт приходить, и его строка остаётся. `OauthToken`
реализует `Prunable`: строки, которых не касались дольше двух `session.lifetime`, именуют
сессию, которой в хранилище давно нет.

Для регулярной уборки используйте готовую команду пакета `uzair:prune` в `routes/console.php`:

```php
use Illuminate\Support\Facades\Schedule;

Schedule::command('uzair:prune')->daily();
```

Команда автоматически нацелена на модель `OauthToken` пакета и поддерживает дополнительные опции:

- `php artisan uzair:prune` — штатный запуск уборки с пакетным отзывом грантов в SSO;
- `--pretend` — отобразить число устаревших токенов без фактического удаления;
- `--chunk=100` — размер чанка при выборке и удалении моделей;
- `--no-revoke` — пропустить удалённый отзыв грантов у UzAirports ID (полезно при ручной пакетной зачистке).

> Команда `uzair:prune` внутри делегирует вызов в стандартный `model:prune` с аргументом `--model=Uzairports\Uzairid\Models\OauthToken`.
> Если вы настраиваете `model:prune` вручную: без явного указания `--model` Laravel ищет модели только в `app/Models`,
> поэтому `OauthToken` из пакета в него не попадает (`No prunable models found`). Если в приложении уже запланирован общий
> `model:prune` с перечислением моделей, добавьте в него `OauthToken::class`.

Чтобы «не касались» означало «браузер не приходил», а не «токен не обновлялся», `uzair.token`
продлевает строку, пока запросы идут, — не чаще одного раза за половину `session.lifetime`,
так что это одна запись в час при настройках по умолчанию, а не запись на каждый запрос.

> Поэтому `uzair.token` и должен висеть на **всех** аутентифицированных маршрутах. Иначе вход,
> чей access-токен живёт дольше окна уборки (восьмичасовой токен при `session.lifetime=120`),
> останется нетронутым, пока владелец работает, — и `model:prune` удалит его из-под живого
> пользователя.

Уборка — единственный запрос пакета без `user_id` рядом: она проходит по таблице одним
`updated_at`. Поэтому по нему стоит индекс. Все остальные запросы называют аккаунт и
обслуживаются уникальной парой `(user_id, session_id)`.

Собирая строку, уборка отдаёт её грант SSO — тем же отзывом, что и обычный выход. Удаление
строки само по себе UzAirports ID ни о чём не сообщает: закрытый браузер не выходил, и его
refresh-токен остаётся действующим, пока провайдер не снимет его сам. Это единственный путь,
на котором вход мог бы закончиться с живым грантом, — поэтому он ведёт себя как остальные.
Отказ SSO пишется в лог и не поднимается: строка называет сессию, которой давно нет, и
оставлять её до завтрашней уборки незачем.

Каждая строка стоит тех запросов отзыва, которые предоставляет провайдер, а уборка может
идти по тысячам строк. Если такой объём реален, а гранты у вас и так истекают сами:

```env
UZAIR_REVOKE_ON_PRUNE=false
```

## Единственная сессия

Если одновременная работа с нескольких устройств — то, что вам нужно запретить:

```env
UZAIR_SINGLE_SESSION=true
```

Тогда вход завершает все остальные входы аккаунта. Учтите: полагаться это будет на то, что
ваш `/api/oauth/logout` гасит грант переданного токена. Если он завершает SSO-сессию
учётной записи целиком, отзыв старого токена заденет и только что выданный.
